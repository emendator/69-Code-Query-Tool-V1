# 69码查询器 — 登录与权限系统 数据库设计

> 版本: v1.0
> 日期: 2026-08-06
> 数据库: SQLite 3（多库方案）
> 关联文档: 《需求分析-登录权限系统.md》《技术方案-登录权限系统.md》

---

## 1. 库结构总览

本系统采用**一主库 + 多公司库**的结构：

| 库 | 文件 | 用途 |
|----|------|------|
| 主库 | `data/69code.db` | 系统级数据：用户、公司、邀请码（本设计新增） |
| 公司库 | `data/companies/company_{company_id}.db` | 业务数据：products / semantic_mappings / column_config（复用现有结构） |

> 公司库文件名中的 `{company_id}` 即主库 `companies.id`。

## 2. 主库 — 新增表

### 2.1 `users` — 用户表

```sql
CREATE TABLE IF NOT EXISTS users (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    username        TEXT    NOT NULL UNIQUE,
    password_hash   TEXT    NOT NULL,
    email           TEXT    NOT NULL UNIQUE,
    role            TEXT    NOT NULL CHECK(role IN ('super_admin','admin','user')),
    company_id      INTEGER,                          -- 所属公司 (super_admin 必有)
    status          TEXT    NOT NULL DEFAULT 'active' -- active | expired | disabled
    expires_at      TEXT,                             -- 账号有效时间(ISO, 可空=永久)
    invited_by      INTEGER,                          -- 邀请其注册的管理员 id (super_admin 为空)
    invite_code_id  INTEGER,                          -- 注册所用邀请码 id
    created_at      TEXT    NOT NULL DEFAULT (datetime('now','localtime')),
    last_login_at   TEXT,                             -- 最后一次登录时间
    FOREIGN KEY (company_id)     REFERENCES companies(id),
    FOREIGN KEY (invited_by)     REFERENCES users(id),
    FOREIGN KEY (invite_code_id) REFERENCES invite_codes(id)
);

CREATE INDEX idx_users_company   ON users(company_id);
CREATE INDEX idx_users_role      ON users(role);
CREATE INDEX idx_users_invitedby ON users(invited_by);
CREATE INDEX idx_users_expires   ON users(expires_at);
```

**字段说明**

| 字段 | 说明 |
| ------ | ------ |
| `username` | 登录名，全局唯一，创建后不可修改 |
| `password_hash` | bcrypt 哈希，禁止明文 |
| `email` | 绑定邮箱，全局唯一 |
| `role` | 角色：`super_admin` / `admin` / `user`，由注册方式决定，不可修改 |
| `company_id` | 所属公司，即其 69 码库 |
| `status` | `active` 正常；`expired` 已到期（可延长恢复）；`disabled` 被禁用 |
| `expires_at` | 账号有效期，空=永久；到期则禁止登录 |
| `invited_by` | 上级（分发邀请码的管理员），级联删除依据 |
| `invite_code_id` | 注册所用邀请码 |
| `created_at` | 注册时间（用户管理界面展示） |
| `last_login_at` | 最后一次登录时间（登录成功时更新） |

### 2.2 `companies` — 公司表

```sql
CREATE TABLE IF NOT EXISTS companies (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    name             TEXT    NOT NULL UNIQUE,          -- 创建后不可修改
    db_password_hash TEXT    NOT NULL,                 -- 公司数据库密码(bcrypt)
    db_file          TEXT    NOT NULL,                 -- 公司库文件名 company_{id}.db
    created_by       INTEGER,                          -- 创建者
    created_at       TEXT    NOT NULL DEFAULT (datetime('now','localtime')),
    updated_at       TEXT,                             -- 密码修改时间
    FOREIGN KEY (created_by) REFERENCES users(id)
);
```

**字段说明**

| 字段 | 说明 |
| ------ | ------ |
| `name` | 公司名，唯一，注册时提示不可修改，系统也不提供修改入口 |
| `db_password_hash` | 公司数据库密码哈希；「加入公司」校验、管理员可修改 |
| `db_file` | 冗余存储公司库文件名，便于运维定位 |
| `created_by` | 创建该公司的账号 |

**初始化数据**（首次启动幂等插入）：

```sql
-- 公司
INSERT INTO companies (name, db_password_hash, db_file, created_by)
VALUES ('我的公司', '<bcrypt("<初始口令>")>', 'company_1.db', NULL);

-- 超级管理员
INSERT INTO users (username, password_hash, email, role, company_id, status, invited_by, invite_code_id)
VALUES ('admin', '<bcrypt("<初始口令>")>', '<管理员邮箱>', 'super_admin', 1, 'active', NULL, NULL);
```

> 初始化流程：创建公司 → 创建 super_admin → 创建该公司库文件并建表。全部幂等（`INSERT OR IGNORE` 或先查后插）。

### 2.3 `invite_codes` — 邀请码表

```sql
CREATE TABLE IF NOT EXISTS invite_codes (
    id                  INTEGER PRIMARY KEY AUTOINCREMENT,
    code                TEXT    NOT NULL UNIQUE,
    level               INTEGER NOT NULL CHECK(level IN (1,2)),  -- 1=管理员 2=用户
    issued_by           INTEGER NOT NULL,                        -- 分发者(管理员/超管)
    status              TEXT    NOT NULL DEFAULT 'unused',       -- unused | used | revoked
    expires_at          TEXT,                                    -- 邀请码有效时间(空=永久)
    account_expires_at  TEXT,                                    -- 用此码注册的账号默认有效期(空=永久)
    used_by             INTEGER,                                 -- 使用人 id
    used_at             TEXT,                                    -- 使用时间
    created_at          TEXT    NOT NULL DEFAULT (datetime('now','localtime')),
    FOREIGN KEY (issued_by) REFERENCES users(id),
    FOREIGN KEY (used_by)  REFERENCES users(id)
);

CREATE INDEX idx_invites_status ON invite_codes(status);
CREATE INDEX idx_invites_level  ON invite_codes(level);
CREATE INDEX idx_invites_issuer ON invite_codes(issued_by);
```

**字段说明**

| 字段 | 说明 |
| ------ | ------ |
| `code` | 邀请码字符串（高熵随机，如 `8`~`12` 位大写字母+数字） |
| `level` | 1=注册管理员；2=注册用户 |
| `issued_by` | 分发者；权限校验：发 1 级码必须是 super_admin |
| `status` | `unused` 可用 → 注册成功后 `used`；分发者可 `revoked` 撤销 |
| `expires_at` | 邀请码过期时间，过期不可注册 |
| `account_expires_at` | 新注册账号继承的有效期 |

### 2.4 主库其他表

- `login_logs`（可选，本期不做，预留）：记录登录成功/失败，便于后续审计。

## 3. 公司库 — 复用现有结构

每个公司库 `company_{id}.db` 包含与现有主库完全一致的 3 张业务表：

- `products` — 69码业务数据（唯一索引 `code`）
- `semantic_mappings` — 语义库
- `column_config` — 列配置（含 `view_type`）

> 建表通过 `BizBase.metadata.create_all(bind=company_engine)`，首次访问公司时懒创建（幂等）。DDL 见《数据库设计.md》第 2~4 节，不再重复。

```
                                               │ 1:N invited_by
┌────────────────────┐    1:N     ┌────────────┴────────────┐
│   invite_codes     │◄───────────│        (users)          │
├────────────────────┤ issued_by  ├─────────────────────────┤
│ id (PK)            │            │  · 用户管理/级联删除     │
│ code (UQ)          │            └─────────────────────────┘

│ status             │

│ account_expires_at │
│ used_by (FK)       │
│ used_at            │
└────────────────────┘

┌──────────────────────────────┐
│ 公司库 company_{id}.db        │  ← 每个公司一个
├──────────────────────────────┤
│ products / semantic_mappings │
│ column_config                │
└──────────────────────────────┘
```

**关联规则（级联删除）**

- 删除 `admin` 账号（仅 super_admin 可操作）时：删除 `users WHERE invited_by = 该admin AND role = 'user'`；
- 删除账号时：仅逻辑删除其所属邀请码关联（邀请码已 used 保留作审计），不物理改邀请码。

## 5. 关键 SQL

### 5.1 账号到期判断

```sql
SELECT * FROM users WHERE id = :id AND status = 'active'
  AND (expires_at IS NULL OR expires_at > :now);
```

### 5.2 邀请码校验（注册前）

```sql
SELECT * FROM invite_codes
WHERE code = :code AND status = 'unused'
  AND (expires_at IS NULL OR expires_at > :now);
```

### 5.3 级联删除（事务）

```sql
-- 统计
SELECT COUNT(*) FROM users WHERE invited_by = :admin_id AND role = 'user';
-- 删除
DELETE FROM users WHERE invited_by = :admin_id AND role = 'user';
DELETE FROM users WHERE id = :admin_id;
```

### 5.4 管理员账号管理范围

```sql
-- admin 可见账号 = 本账号 + 自己邀请的账号
SELECT * FROM users
WHERE id = :me
   OR invited_by = :me;
```

### 5.5 到期账号列表

```sql
SELECT * FROM users
WHERE expires_at IS NOT NULL AND expires_at <= :now AND status != 'expired';
```

## 6. 迁移策略（旧库升级）

- 现有 `69code.db` 只有 3 张业务表，无系统表；
- 首次启动：`MasterBase.metadata.create_all` 自动补建 `users / companies / invite_codes`；
- 若 `companies` 为空 → 执行初始化（我的公司 + admin + 公司库）；
- **重要**：需将现有业务数据从主库迁移到公司库 `company_1.db`（初始化时执行一次：从旧 `products` 复制到公司库，然后**保留或清理旧表**——建议保留原表名但业务层不再使用，或直接复制后删除，二选一并在实现时确认）。
  - 若原主库同时承担业务表与系统表，为减少风险，推荐：**主库继续保留业务表作为迁移源**，公司库为业务新家；迁移完成、验证无误后再物理删除旧业务表。
- 索引/约束与现有设计一致，无破坏性变更。

## 7. ORM 分层建议

为避免主库误建业务表、公司库误建系统表，将模型按基类拆分：

```python
# backend/models.py
from database import MasterBase, BizBase

# 系统表
class User(MasterBase):      __tablename__ = "users"
class Company(MasterBase):   __tablename__ = "companies"
class InviteCode(MasterBase):__tablename__ = "invite_codes"

# 业务表
class Product(MasterBase, BizBase):  __tablename__ = "products"
...
```

实现时建议：

- `database.py` 定义 `MasterBase`（系统表）与 `BizBase`（业务表）两个 `declarative_base()`；
- `MasterBase.metadata.create_all(master_engine)` 只建系统表；
- `BizBase.metadata.create_all(company_engine)` 只建业务表；
- 主库与公司库的连接/Session 分别使用独立 `sessionmaker`，杜绝串库。

> 注意：现有 `Product / SemanticMapping / ColumnConfig` 从 `Base` 继承，改造时需切换基类并全量回归测试（查询/导入/导出/配置）。
