## 1. 技术栈选型

| 层级 | 技术 | 版本 | 选型理由 |
| ------ | ------ | ------ | ---------- |
| **后端框架** | Python FastAPI | ≥ 0.110 | 异步高性能，自动生成 OpenAPI 文档，类型校验 |

| **前端构建** | Vite 5 | ≥ 5 | 极速 HMR，按需编译 |

| **表格解析** | pandas + openpyxl | pandas ≥ 2.0 | 支持 xlsx/xls/csv 多种格式 |
| **模糊匹配** | difflib (标准库) | - | 内置，零依赖，适合列名模糊匹配 |
| **运行环境** | Python 3.10+ / Node.js 18+ | - | LTS 版本 |

## 3. 后端 API 设计

### 3.1 查询接口

```
GET  /api/query/single?code=6901234567890
     → { success: true, data: { ... } | null }

POST /api/query/batch
     Body: { codes: ["690...", "690...", ...] }
     → { success: true, data: [{ code, found: true, row: {...} }, ...] }

POST /api/query/export
     Body: { codes: [...], columns: [...] }
     → 返回 Excel 文件 (Content-Disposition: attachment)
```

### 3.2 数据管理接口

```
GET    /api/data?page=1&page_size=50&search=&sort_by=id&sort_order=asc
       → { success: true, data: { items: [...], total: N, page: N, page_size: N } }

POST   /api/data          (新增)
       Body: { model: "", name: "", code: "", remark: "" }
       → { success: true, data: { ... } }

PUT    /api/data/{id}     (编辑)
       Body: { model: "", name: "", code: "", remark: "" }
       → { success: true, data: { ... } }

DELETE /api/data/{id}     (删除单条)
       → { success: true }

POST   /api/data/batch-delete
       Body: { ids: [1, 2, 3] }
       → { success: true }

POST   /api/data/deduplicate
       → { success: true, deleted_count: N }
```

### 3.3 导入接口

```
POST  /api/import/upload
      Body: multipart/form-data (file)
      → { success: true, data: { columns: ["列1", "列2", ...], rows: N, preview: [...] } }

POST  /api/import/match-columns
      Body: { file_columns: ["列1", "列2", ...] }
      → { success: true, data: { matches: { 型号: "列X", 品名: "列Y", 69码: "列Z" }, confidence: "high|medium|low" } }

POST  /api/import/confirm
      Body: { filename: "...", column_mapping: {...}, add_to_semantic: boolean }
      → { success: true, imported_count: N }

POST  /api/import/add-semantic
      Body: { source_column: "...", target_field: "型号|品名|69码" }
      → { success: true }
```

### 3.4 配置接口

```
GET  /api/config/columns
     → { success: true, data: { columns: [...] } }

PUT  /api/config/columns
     Body: { columns: [{ field: "model", label: "型号", width: 120, visible: true, order: 1 }, ...] }
     → { success: true }
```

## 4. 智能列匹配算法

### 4.1 匹配流程

```
用户上传文件 → 提取表头列名 → 模糊匹配 → 语义匹配 → 结果
                                    ↓
                              未匹配到? → 用户手动选择 → 可选加入语义库
```

### 4.2 模糊匹配策略

1. **精确匹配**: 列名完全等于已知关键词
2. **包含匹配**: 列名包含已知关键词（不区分大小写）
3. **相似度匹配**: 使用 `difflib.SequenceMatcher` 计算相似度，阈值 ≥ 0.6

### 4.3 语义匹配策略

1. 查询语义库表，查找 `source_column` 与当前列名匹配的记录
2. 语义库存储结构:

   ```json
   { "source_column": "产品条码", "target_field": "69码", "added_by": "user", "created_at": "..." }
   ```

3. 同时维护一组**内置默认关键词**作为初始语义库:
   - 型号类: `["型号", "规格", "产品型号", "物料号", "料号", "产品编号", "货号", "编号", "model", "part number", "pn"]`
   - 品名类: `["品名", "名称", "产品名称", "商品名", "描述", "产品描述", "name", "product name", "description"]`
   - 69码类: `["69码", "条码", "条形码", "商品条码", "EAN", "EAN13", "barcode", "code", "upc"]`

### 4.4 置信度判定

| 条件 | 置信度 |
| ------ | -------- |
| 精确匹配内置关键词或语义库 | high |
| 包含匹配或相似度 ≥ 0.8 | high |
| 相似度 0.6~0.8 | medium |
| 无任何匹配 | low (需用户手动指定) |

## 5. 前端状态管理

- **不使用 Redux**，使用 React 内置 `useState` + `useContext` 管理全局状态
- 全局 Context 提供: 列配置、主题等
- 页面级状态由各页面组件自行管理
- API 请求使用 Axios 封装，统一错误处理

---

## 6. 列配置持久化

- 列配置（顺序、显示名、宽度、可见性）存储于后端的 `config` 表
- 前端在应用启动时加载配置
- 修改配置后自动保存

---

## 7. 去重策略

- **去重依据**: 69 码字段（唯一标识）
- **保留规则**: 保留 `id` 最小的记录（最早导入），删除后续重复
- **前端高亮**: 查询数据库时后端标记重复项，前端用红色/警告色高亮
- **一键去重**: 调用 `POST /api/data/deduplicate`，在后端完成事务性删除

---

## 8. 安全与边界

- CORS 仅允许前端来源（开发模式: `http://localhost:5173`）
- 上传文件大小限制: 最大 50MB
- 上传文件类型白名单: `.xlsx`, `.xls`, `.csv`
- SQLite WAL 模式开启，提升并发读取性能
- 所有用户输入在写入数据库前进行转义/SQL 参数化（SQLAlchemy 特性）
