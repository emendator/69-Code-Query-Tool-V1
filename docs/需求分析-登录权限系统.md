## 1. 项目背景与目标

现有「69码查询器」为无登录的本地/单机工具，任何人打开即用，所有用户共享同一份 69 码数据库。

本次升级目标是引入**完整的账户体系与三级权限**，实现：

1. **登录 / 注册**功能，密码加密存储；
2. **三级权限**：最高级管理员 > 管理员 > 用户；
3. **邀请码注册制**：一级邀请码注册管理员、二级邀请码注册用户，邀请码一次性作废；
4. **公司维度数据隔离**：不同公司的账号使用**各自独立的 69 码库**；
5. **账号有效期管理**：邀请码和账号均支持有效期，到期禁止登录；
6. **用户管理界面**：管理邀请码、账号、有效期、级联清除。

## 2. 角色与权限矩阵

### 2.1 角色定义

| 角色 | 英文标识 | 说明 |
| ------ | --------- | ------ |
| 最高级管理员 | `super_admin` | 系统最高权限，唯一。**即"我"**，用户名 `admin`，密码 `<初始口令>`，公司固定为「我的公司」 |
| 管理员 | `admin` | 通过一级邀请码注册。可创建/加入公司，管理本公司用户 |
| 用户 | `user` | 通过二级邀请码注册。仅能加入已有公司，使用业务功能 |
| 游客 | `guest` | 登录页「以游客身份登录」，无需账号密码。可使用全部业务功能，**无用户管理界面**，数据不保留，退出后自动清除全部使用痕迹 |

### 2.2 权限矩阵

| 功能 | super_admin | admin | user | guest |
| ------ | :---: | :---: | :---: | :---: |
| 登录 / 修改自己密码 | ✅ | ✅ | ✅ | ❌（无密码） |
| 69码查询（单码/批量/导出） | ✅ | ✅ | ✅ | ✅ |
| 数据管理（增删改查/导入/导出/去重） | ✅ | ✅ | ✅ | ✅ |
| 列配置 | ✅ | ✅ | ✅ | ✅ |
| 分发**一级邀请码**（注册管理员） | ✅ | ❌ | ❌ | ❌ |
| 分发**二级邀请码**（注册用户） | ✅ | ✅ | ❌ | ❌ |
| 查看/管理邀请码 | ✅（全部） | ✅（自己分发的） | ❌ | ❌ |
| 查看/管理账号（有效期/清除/延长） | ✅（全部） | ✅（本账号+自己邀请的账号） | ❌ | ❌ |
| 修改**公司数据库密码** | ✅ | ✅（本公司的） | ❌ | ❌ |
| 级联清除（删除管理员→连带其下用户） | ✅ | ❌ | ❌ | ❌ |

> 注：游客使用独立的临时 69 码库（会话级），数据不持久化；退出登录后游客用户、临时公司与 69 库文件、上传文件全部自动清除。界面在登录页与主界面均有「游客模式不保留数据」提醒。

### 2.3 默认超级管理员

| 项目 | 值 |
| ------ | ----- |
| 用户名 | `admin` |
| 密码 | `<初始口令>` |
| 角色 | `super_admin` |
| 所属公司 | `我的公司` |
| 公司数据库密码 | `<初始口令>` |
| 有效期 | 永久（不设有效期） |

> 系统首次启动（初始化）时自动创建该账号与该公司，并创建对应的公司库。若主库已存在则跳过（幂等）。

## 3. 功能需求

### 3.1 登录（F-AUTH-01）

- 输入项：**用户名 + 密码**
- 校验失败（用户名不存在 / 密码错误）时给出统一提示，避免暴露账号是否存在
- 登录成功后返回登录凭证（JWT），前端保存并可自动恢复登录态
- 记录**最后一次登录时间**（`last_login_at`）
- **有效期检查**：账号有效期已到 → 拒绝登录，提示「账号有效期已到，请联系管理员」

### 3.2 注册（F-AUTH-02）

注册输入项：

| 输入 | 必填 | 说明 |
| ------ | :---: | ------ |
| 用户名 | ✅ | 全系统唯一，创建后不可修改 |
| 密码 | ✅ | 长度 ≥ 6，加密存储（bcrypt） |
| 邮箱 | ✅ | 格式校验，唯一 |
| 邀请码 | ✅ | 校验其级别与有效性 |
| 公司名称 | ✅ | 见 3.4 |
| 公司数据库密码 | ✅ | 见 3.4 |

注册规则：

1. 校验邀请码：
   - 必须存在、状态为 `unused`、未超过邀请码有效期；
   - **一级邀请码 → 注册为管理员**；**二级邀请码 → 注册为用户**；
   - 校验通过后**立即作废**（置为 `used`），每个邀请码只能使用一次。
2. 按角色走公司流程（见 3.4）。
3. 账号有效期：默认继承邀请码上设置的 `account_expires_at`（分发邀请码时可指定），未指定则永久。
4. 记录账号来源：`invited_by`（分发邀请码的管理员）、`invite_code_id`。

### 3.3 邀请码体系（F-AUTH-03）

| 属性 | 说明 |
| ------ | ------ |
| 级别 | `1`（管理员注册用）/ `2`（用户注册用） |
| 生成 | 后端随机生成（如 `secrets`），长度 8~12，大写字母+数字，不可预测、不可枚举 |
| 有效期 | 分发时可设置 `expires_at`，过期后不可用于注册 |
| 账号默认有效期 | 分发时可设置 `account_expires_at`，使用该码注册的账号继承此有效期（可空=永久） |
| 一次性 | 注册成功后立即作废（`used`），不可重复使用 |
| 可撤销 | 分发者可撤销未使用的邀请码 |

**分发权限**：

- 最高级管理员：可分发一级 + 二级邀请码；
- 管理员：只能分发二级邀请码。

### 3.4 公司与数据库隔离（F-AUTH-04）

#### 3.4.1 核心原则

> 「权限分级目前仅在数据库上有区分，以账户注册时输入的公司名和公司数据库密码为分割，同一个公司的账号使用同一个 69 码库。」

- **每个公司 = 一个独立 SQLite 数据库文件**（`company_{company_id}.db`），存放该公司的 products / semantic_mappings / column_config 等全部业务数据；
- 同一公司的所有账号（无论角色）访问**同一个公司库**；
- 公司名称全系统唯一，**创建后不可修改**（注册时明确提示用户）；
- 公司数据库密码：注册时的校验凭据，各公司管理员可修改。

#### 3.4.2 注册时的公司选择

| 场景 | 流程 |
|------|------|
| **管理员注册**（一级码） | 二选一：<br>① **创建新公司**：输入公司名称 + 设置公司数据库密码（提示「公司名填写后不可修改」）；<br>② **加入公司**：输入公司名称 + 公司数据库密码，校验公司存在且密码正确 |
| **用户注册**（二级码） | 仅能**加入公司**：输入公司名称 + 公司数据库密码，校验同上 |

#### 3.4.3 公司数据库密码

- 存储为哈希（bcrypt），不存明文；
- 「加入公司」时用于校验用户是否有权加入该公司；
- 管理员的权限账户可**修改本公司数据库密码**（需校验原密码）；
- 修改后不影响已注册账号登录（仅影响后续加入公司的校验）。

#### 3.4.4 默认公司

- 最高级管理员初始化时自动创建：公司名 `我的公司`，公司数据库密码 `<初始口令>`；
- 其公司库文件 `company_{id}.db` 在初始化时创建并建表。

### 3.5 用户管理界面（F-AUTH-05）

**入口**：最高级管理员、管理员可见（用户不可见）。

#### 3.5.1 邀请码管理

- 展示邀请码列表：邀请码、级别、状态（未使用/已使用/已撤销）、有效期、账号默认有效期、注册人、分发时间；
- 「分发新邀请码」：选择级别（按权限限制）、设置邀请码有效期、设置账号默认有效期；
- 可撤销未使用的邀请码。

#### 3.5.2 账号管理

- 展示账号列表（分页 + 搜索）：用户名、角色、所属公司、邮箱、**注册时间**、**最后一次登录时间**、**有效期**、状态；
- **数据范围**：
  - 最高级管理员：全部账号；
  - 管理员：本账号 + 自己邀请的账号（见 3.5.4）；
- 操作：
  - **延长有效期**：设置新的到期时间；
  - **清除账号**：删除到期/无效账号（未到期账号清除时二次确认）；
  - **级联清除**：最高级管理员删除**管理员账号**时，该管理员邀请的所有 `user` 账号**同步清除**。

#### 3.5.3 有效期规则

- 邀请码：过期后不能用于注册；
- 账号：到期后**禁止登录**，登录时提示「账号有效期已到，请联系管理员」；
- 到期账号仍在列表中展示（状态=已过期），供管理员延长或清除。

#### 3.5.4 管理员的数据范围规则（明确边界）

- 管理员账号列表 = **本账号 + 本账号邀请的账号**（`id = 我` 或 `invited_by = 我`），看不到其他账号；
- 管理员**只能管理自己邀请的账号**（延长/清除），不能管理自己与其他账号；
- 最高级管理员可看到并管理一切（删除管理员时级联删除其邀请的用户）。

### 3.6 业务数据隔离（F-AUTH-06）

- 登录后，所有业务接口（查询、数据管理、导入、导出、去重、列配置）**只操作当前用户所属公司的公司库**；
- 不同公司之间数据完全隔离，互不可见；
- 未登录 / 凭证失效时，业务接口返回 401。

### 3.7 界面要求（F-UI-01）

- **登录页**：美观、大气、简约。居中卡片式布局，品牌化配色（可沿用主题色 `#1677ff`），渐变背景、圆角、阴影、Logo/标题；
- **注册页**：与登录页风格统一；邀请码级别影响公司选项（创建/加入）的显示；
- **登录/注册切换**：登录页提供「去注册」入口，注册页提供「去登录」入口；
- **主界面**：顶栏显示当前用户名、角色、公司名、剩余有效期提示、「退出登录」按钮；侧栏菜单按角色过滤（用户管理菜单仅 super_admin/admin 可见）；
- **到期提醒**：账号剩余有效期不足时（如 ≤ 7 天）在界面醒目提示；登录被拒时明确提示原因。

## 4. 非功能需求

| ID | 需求 | 说明 |
| ---- | ------ | ------ |
| N-01 | 密码安全 | 密码 bcrypt 哈希存储（salt 自动生成），禁止明文 |
| N-02 | 登录凭证 | JWT，服务端签名，设置合理过期时间；前端请求头携带 `Authorization: Bearer <token>` |
| N-03 | 邀请码安全 | 随机不可预测；一次一码；过期/撤销机制 |
| N-04 | 数据隔离 | 公司库物理隔离（独立文件），代码层严格按 `company_id` 路由 |
| N-05 | 兼容性 | 兼容现有启动方式（`启动.bat` / `start.ps1`），前端 5178、后端 8005 端口不变，生产 Nginx 端口不变 |
| N-06 | 向后兼容 | 现有业务 API 改造后行为不变（登录态下功能等价） |
| N-07 | 响应性能 | 认证接口 < 1s；业务接口不因鉴权明显变慢 |
| N-08 | 数据库迁移 | 主库新增表自动创建；公司库懒创建（首次访问某公司时建表） |

## 5. 异常与边界情况

| # | 场景 | 处理 |
| --- | ------ | ------ |
| 1 | 邀请码不存在 / 已使用 / 已撤销 / 已过期 | 注册拒绝，提示具体原因 |
| 2 | 用户名重复 / 邮箱重复 | 注册拒绝，提示「用户名已存在」/「邮箱已被注册」 |
| 3 | 公司名已存在且选择「创建新公司」 | 拒绝创建，提示改名，或引导「加入公司」 |
| 4 | 「加入公司」密码错误 | 拒绝，提示「公司或密码不正确」 |
| 5 | 账号到期后登录 | 拒绝登录，提示「账号有效期已到，请联系管理员」 |
| 6 | 有效期期间凭证过期（Token 过期） | 前端跳转登录页重新登录 |
| 7 | 有效期到期时已登录 | 每次请求鉴权时检查，返回 401/403，前端强制登出 |
| 8 | 管理员删除时级联删除其用户 | 事务内完成；若用户量大需提示删除数量并二次确认 |
| 9 | 清除正在使用的管理员 | 二次确认；其 token 立即失效（服务端按用户禁用/删除校验） |
| 10 | 公司库文件缺失/损坏 | 重新创建（建表幂等），业务数据丢失需人工处理 |
| 11 | super_admin 被误删 | 系统保证 super_admin 不可被删除（删除接口校验） |
| 12 | 修改公司数据库密码 | 校验原密码；成功后提示「已修改，后续加入公司需使用新密码」 |

## 6. 验收标准

1. 未登录访问任何页面/接口均被拦截，跳转登录页；
2. `admin / <初始口令>` 可登录，角色为最高级管理员，公司为我的公司；
3. 密码在数据库中为哈希值，无明文；
4. 一级邀请码可注册管理员（可创建/加入公司）；二级邀请码可注册用户（仅加入公司）；邀请码用后即废；
5. 创建公司时提示「公司名填写后不可修改」，且创建后确实不可修改；
6. 同一公司账号共用同一 69 码库；不同公司数据互不可见；
7. 管理员可修改本公司数据库密码（需原密码）；
8. super_admin 与 admin 可见用户管理界面；user 不可见；
9. 邀请码/账号设有效期后，到期账号无法登录并收到明确提示；
10. 可延长账号有效期、清除到期账号；
11. super_admin 删除管理员时，其邀请的用户同步删除；
12. 登录/注册界面美观大气简约，风格统一。

## 7. 范围说明（本次不做）

- 不实现邮箱验证码/找回密码（邮箱仅作绑定与唯一标识）；
- 不做前端路由级别的细粒度按钮权限（本次按菜单/页面级控制即可）；
- 不做多公司管理员对同一公司的协同管理界面（后续可扩展）；
- 不修改用户角色（角色在注册时由邀请码级别决定）。
