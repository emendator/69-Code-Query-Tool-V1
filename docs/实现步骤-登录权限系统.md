### 步骤 2.4 — 邀请码生成工具

`backend/security.py` 或 `backend/utils.py`：

```python
import secrets, string
def generate_invite_code(length=10) -> str:
    alphabet = string.ascii_uppercase + string.digits
    # 排除易混淆字符 O/0/I/1
    alphabet = "ABCDEFGHJKLMNPQRSTUVWXYZ23456789"
    return "".join(secrets.choice(alphabet) for _ in range(length))
```

### 步骤 3.2 — Schemas

`backend/schemas.py` 追加：

```python
class RegisterCheckInviteRequest(BaseModel):
    invite_code: str

class RegisterRequest(BaseModel):
    username: str = Field(..., min_length=3, max_length=20, pattern=r"^[a-zA-Z0-9_]+$")
    password: str = Field(..., min_length=6, max_length=64)
    email: EmailStr

    company_name: str
    company_db_password: str = Field(..., min_length=1)

class LoginRequest(BaseModel):
    username: str
    password: str

class UserInfo(BaseModel):
    id: int; username: str; role: str; company_id: int|None; company_name: str|None
    email: str; status: str; expires_at: str|None; created_at: str; last_login_at: str|None
    remaining_days: int|None

class LoginResponse(BaseModel):
    token: str
    user: UserInfo

class InviteCreateRequest(BaseModel):
    level: Literal[1, 2]
    expires_at: str|None = None
    account_expires_at: str|None = None

class ExtendUserRequest(BaseModel):

```

### 步骤 3.3 — auth 路由 `backend/routers/auth.py`（或并入 main.py）

按技术方案 §4.1 实现：

- `POST /api/auth/register/check-invite`：校验邀请码（存在/未用/未过期）→ 返回 `{level, company_name?}`；统一错误文案防枚举；
- `POST /api/auth/register`：
  1. 校验邀请码 → 按 level 定角色（1→admin，2→user；**admin 分发 1 级码场景后端禁止**）；
  2. 用户名/邮箱唯一校验；
  3. `mode=create`（仅 level=1 且角色 admin）→ 创建公司（名称唯一）+ 生成公司库；`mode=join` → 校验公司名+公司数据库密码（`verify_password`）；
  4. 创建 user（`expires_at = invite.account_expires_at`，`invited_by = invite.issued_by`，`invite_code_id`）；
  5. 邀请码置 `used`；
  6. 签发 token，返回 `{token, user}`；
- `POST /api/auth/login`：查用户 → 验密码 → 查状态/有效期（到期返回 `success:false` + 明确提示）→ 更新 `last_login_at` → 签发 token；
- `GET /api/auth/me`：返回 UserInfo（含 company_name、remaining_days）；
- `PUT /api/auth/company/password`：admin/super_admin 校验 `old_db_password` → 更新公司 `db_password_hash`。

**验收**：curl/浏览器可直接注册、登录、取 me；到期账号登录被拒；密码以哈希入库。

## 阶段五：业务 API 鉴权与公司库路由（1 天）

改造 `backend/main.py` 中现有业务路由：

| 路由 | 改动 |
| ------ | ------ |
| `/api/query/*` | `db: Session = Depends(get_company_db)` + 前置 `Depends(get_current_user)` |
| `/api/data/*` | 同上 |
| `/api/import/*` | 同上；`upload-temp` 保存目录改为 `data/upload/company_{id}/`，路径消毒逻辑保留 |
| `/api/config/*` | 同上 |

要点：

- 每个业务路由函数签名改为：`def xxx(..., user=Depends(get_current_user), db=Depends(get_company_db))`；
- `get_company_db` 内部依赖 `get_current_user`，保证先鉴权后取库；
- 移除原来直接 `Depends(get_db)` 的业务路由（保留给系统表接口用）。

**验收**：无 token 访问业务接口返回 401；不同公司账号只能看到各自数据。

### 9.1 联调清单

1. 初始化：旧库升级后 admin/<初始口令> 可登录，旧业务数据在默认公司库可查；
